# 전표리더

세금계산서 · 거래명세서 · 발주서를 읽어 **ERP 입력용 데이터**로 바꾸는 백오피스 자동화 도구입니다.

## 이 제품이 파는 것

"AI가 전표를 읽어준다"는 이미 상품이 아닙니다. 경리 담당자는 자동 입력이 99% 맞아도
**나머지 1%를 찾느라 전수 검토를 하고, 그러면 자동화 가치가 0이 됩니다.**

그래서 이 제품의 본체는 추출이 아니라 **검증 엔진**입니다.
기계가 판정 가능한 규칙을 전부 돌려서 전표마다 셋 중 하나로 가릅니다.

| 판정 | 뜻 | 담당자 행동 |
| --- | --- | --- |
| 자동 승인 가능 | 지적사항 없음 | 그대로 ERP에 올림 |
| 확인 권장 | 경고만 있음 (영세율, 세액 10% 불일치 등) | 눈으로 한 번 봄 |
| 사람 검토 필요 | 오류 있음 (체크섬 실패, 금액 불일치 등) | 반드시 대조 |

검증에는 **모델을 쓰지 않습니다.** 추출한 모델에게 채점까지 맡기면
같은 실수를 같은 방향으로 반복하기 때문에, 전부 결정적 규칙으로 짰습니다.

## 검증 규칙

- **사업자등록번호 체크섬** — 국세청 검증식(가중치 `[1,3,7,1,3,7,1,3,5]`)으로 대조.
  OCR 오인식이 가장 자주 나는 필드라 한 자리만 틀려도 걸립니다.
- **공급가액 + 세액 = 합계금액**
- **품목 공급가액 합계 = 전표 공급가액** (행 누락 탐지)
- **품목 세액 합계 = 전표 세액** (부분 수정 후 불일치 탐지)
- **세액 = 공급가액 × 10%** — 다르면 경고 (영세율·면세는 반려하지 않음)
- **수량 × 단가 = 품목 공급가액**
- **작성일자** — 달력상 실재 여부, 미래 날짜, 5년 초과 경과(연도 오인식)
- **공급자 ≠ 공급받는자**

규칙은 `src/lib/validate.ts`에 있고, `scripts/validate.test.mjs`가 **29개 케이스로 검증**합니다.

```bash
npx tsc src/lib/validate.ts src/lib/schema.ts --outDir .testbuild \
  --module esnext --target ES2022 --moduleResolution bundler --skipLibCheck
node scripts/validate.test.mjs
```

## 추출 정확도 측정

`fixtures/tax_invoice.png`와 **손으로 입력한 정답**(`tax_invoice.answer.json`)이 들어 있습니다.
모델이나 프롬프트를 바꿀 때마다 돌려서 점수가 내려가지 않는지 확인하세요.

```bash
GEMINI_API_KEY=... node scripts/verify-extract.mjs fast
GEMINI_API_KEY=... node scripts/verify-extract.mjs accurate
```

> **아직 측정되지 않았습니다.** 개발 환경의 API 크레딧이 소진되어 실제 추출 정확도를
> 확인하지 못했습니다. 추출 요청은 문서화된 스펙에 맞춰 작성했지만 **라이브 검증 전입니다.**
> 키를 넣고 위 스크립트를 먼저 돌려보세요. 모델 티어는 그 점수를 보고 고르면 됩니다.

## 모델 티어

| 티어 | 모델 | 용도 |
| --- | --- | --- |
| 빠름 | `gemini-3.1-flash-lite` | 대량 처리 · 저단가 |
| 정밀 | `gemini-3.8-flash` | 흐린 스캔 · 복잡한 표 |

추출은 전표 1건당 한 번만 돌고 **검증은 공짜**(순수 로직)이므로,
모델 등급이 그대로 건당 원가가 됩니다. 기본값을 저단가 티어로 둔 이유입니다.

## 실행

```bash
npm install
cp .env.example .env.local   # GEMINI_API_KEY 입력
npm run dev
```

API 키는 서버에서만 쓰이고 브라우저로 내려가지 않습니다.
`NEXT_PUBLIC_` 접두사를 붙이면 노출되니 주의하세요.

## 내보내기

품목 단위로 행을 펼친 CSV를 내보냅니다. 대부분의 국내 ERP 전표 업로드 양식이
품목 단위 행을 요구하기 때문입니다. 엑셀에서 한글이 깨지지 않도록 BOM을 붙입니다.

컬럼: 문서종류, 작성일자, 공급자/공급받는자 3종씩, 품목 6종, 전표 합계 3종, 비고, **검증결과**

## 구조

```
src/
├─ app/
│  ├─ page.tsx                 업로드 · 배치 판독 · 요약 · 내보내기
│  └─ api/extract/route.ts     판독 API (추출 → 검증)
├─ components/VoucherCard.tsx  판정 배지 · 지적사항 · 교정 폼
└─ lib/
   ├─ validate.ts              검증 엔진  ← 제품의 본체
   ├─ schema.ts                전표 스키마 + 구조화 출력 JSON Schema
   ├─ gemini.ts                추출 래퍼
   └─ csv.ts                   ERP 업로드용 CSV
fixtures/                      정확도 측정용 샘플 + 정답
scripts/                       검증 엔진 테스트 · 정확도 측정
```

## 알려진 제약

- **PDF는 단일 요청으로 보냅니다.** 여러 장짜리 스캔은 페이지를 나눠 올리세요.
- **ERP 직접 연동은 없습니다.** 현재는 CSV까지입니다. 연동은 고객사 ERP마다 달라
  `lib/csv.ts`의 컬럼 매핑을 교체하는 방식으로 붙입니다.
- **손글씨 전표는 대상이 아닙니다.** 인쇄·전자 발행 전표 기준으로 만들었습니다.
- 생성된 데이터는 회계 신고 자료를 보증하지 않습니다. 최종 확인 책임은 담당자에게 있습니다.
